db-migrate｜PostgreSQL 数据库迁移治理 CLI
BAS 版本发布 / 宕机维护｜结构变更 + 批量数据迁移一体化
技术栈：Go、Cobra、PostgreSQL、YAML、database/sql、pg_stats / pg_class 统计信息、Git
  • 背景：版本升级场景下，数据库变更长期依赖零散 SQL 与人工按目录执行，存在并发重复执行、脚本篡改误跑、大表迁移中断难续跑等高风险问题，且中英文环境初始化数据漏跑/错跑风险突出。
  • 方案：自研 dbmigrate upgrade 统一迁移入口并设计 SQL/YAML 双引擎模型，在同一执行链路中同时支持结构变更与数据迁移，覆盖大数据量迁移、跨表迁移、列映射、一源多目标写入、断点续传等复杂场景。
  • 亮点：
  • YAML 路径采用生产者-消费者模型（goroutine 读源 + channel 背压 + 主循环事务写），实现读写解耦与迁移过程稳态吞吐控制。
  • 落地 migration_lock 互斥锁 + SHA1 内容校验 + 执行记录比对三件套，保障跨进程/跨实例串行执行并拦截已执行脚本篡改风险。
  • 构建 batchSize + transactionSize 分批分事务机制，控制事务边界与锁持有时长，降低大批量迁移失败回滚成本。
  • 实现“源表主键上界 + 目标断点主键（dest_pk ≤ source_max）”续跑算法，支持中断后从断点恢复，缩短故障恢复时间。
  • 基于 pg_class.reltuples 与 pg_stats.histogram_bounds 输出迁移进度与剩余时间日志，增强迁移过程可观测性与执行预期管理。
  • 通过 dbmigrate new 规范命名与稳定排序执行，提升迁移资产的可排序、可追踪、可审计能力。
  • 增加 git status --porcelain 前置校验，阻断脏工作区直接发布，降低人为误操作风险。
  • 结果：形成“SQL 结构变更 + YAML 批量数据迁移”统一治理能力，支撑 changelog 700+ 迁移脚本按序执行与审计，使发布流程由人工执行转为可控、可追踪、可恢复的标准化流程，显著降低版本发布与宕机维护场景下的数据库变更风险。

个人职业操作系统（Personal Career OS）
面向 IT 从业者的垂直 Multi-Agent 产品
技术栈：Python、FastAPI、LangGraph、LiteLLM、React、SSE
  • 背景：传统求职工具主要围绕单次 JD 匹配与简历改写，难以支撑长期职业发展决策。用户常见痛点包括：长期职业目标、能力资产与市场机会彼此割裂；多轮对话结论难沉淀、上下文易漂移；策略推演与简历执行脱节；关键确认节点缺少流程约束；历史产物与决策依据难追踪、难复用。
  • 方案：根据身份、能力、市场三空间统一建模，达成长期职业规划、职业事实与能力资本沉淀。采用“协调者 + 领域 Worker + Harness 运行时”的一主多从 Multi-Agent 架构，设计并落地五层分层架构（交互接入层 API/SSE → 编排层 Coordinator → 执行层 7 类 Worker → 运行时平台层 Harness → 存储层 Profile/Session/Task/Output），以“单入口编排 + 领域隔离执行 + 同进程硬约束”保障多 Agent 流程的可控路由、稳定交付与可追踪演进。
  • 亮点：
  • 设计并实现一主多从 Multi-Agent 架构，协调者负责意图分析、任务调度、回复合成，7 个领域 Worker 专注垂直业务域，Worker 之间零直连，通过协调者统一上下文传递，确保系统可扩展、可调试，避免多入口导致的状态漂移与口径不一致。
  • 通过注册表模式实现 Agent 能力（Worker/Skill/Tool）的配置化管理，新增能力无需修改调度核心代码，符合开闭原则。
  • 设计五阶段任务流（explore -> market -> jd_analysis -> resume_strategy -> resume_optimize）并绑定 advance/jump 路由约束，实现流程推进可控与阶段边界清晰。
  • 8+ 类对话闸门（HITL）采用 硬规则优先 + 轻量 LLM 回退；关键路径（如优化确认、初探完成）通过 Harness 层硬拦截未确认的敏感操作（如简历生成），确保业务流程安全可控。
  • Worker 采用按需加载策略，运行时依据任务进展自主选择并加载 Tool、Skill，避免不必要的 Token 消耗，同时支持动态切换执行策略。
  • 落地 context 治理机制：协调者根据当前阶段和用户意图动态选择相关字段注入上下文（goal、skill_index、profile 相关字段等）；对话历史窗口裁剪，Worker 不读全量会话，降低上下文污染与 token 浪费并保持相关性。
  • 设计基于 Worker 的 Profile 写入权限模型，通过路径白名单控制各 Agent 写入范围，Harness 运行时做硬校验防止越权修改。
