
## 简历正文（推荐粘贴）

**个人职业规划系统（Personal Career OS）** | Python · FastAPI · LangGraph · LiteLLM · React · SSE

背景：

传统求职工具主要围绕单次 JD 匹配与简历改写，难以支撑长期职业发展决策。用户常见痛点包括：长期职业目标、能力资产与市场机会彼此割裂；多轮对话结论难沉淀、上下文易漂移；策略推演与简历执行脱节；关键确认节点缺少流程约束；历史产物与决策依据难追踪、难复用。

方案：

根据**身份、能力、市场**三空间统一建模，达成长期职业规划、职业事实与能力资本沉淀。采用“协调者 + 领域 Worker + Harness 运行时”的一主多从 Multi-Agent 架构，**设计并落地五层分层架构**（交互接入层 API/SSE → 编排层 Coordinator → 执行层 7 类 Worker → 运行时平台层 Harness → 存储层 Profile/Session/Task/Output），以“**单入口编排 + 领域隔离执行 + 同进程硬约束**”保障多 Agent 流程的**可控路由、稳定交付与可追踪演进**。

- 设计并实现了**一主多从 Multi-Agent 架构**，协调者负责**意图分析、任务调度、回复合成**，7 个领域 Worker 专注垂直业务域，Worker 之间**零直连**，通过协调者统一上下文传递，上游结论经 Harness 落档后注入下游确保系统**可扩展、可调试**，避免多入口导致的**状态漂移与口径不一致**。

- 通过**注册表模式**实现 Agent 能力（Worker/Skill/Tool）的**配置化管理**，新增能力无需修改调度核心代码，符合**开闭原则**。

- 设计**五阶段任务流**（explore -> market -> jd_analysis -> resume_strategy -> resume_optimize）并绑定 **advance/jump 路由约束**，实现**流程推进可控与阶段边界清晰**。

- **8+ 类对话闸门（HITL）**采用 **硬规则优先 + 轻量 LLM 回退**；关键路径（如优化确认、初探完成）通过 Harness 层**硬拦截**未确认的敏感操作（如简历生成），确保业务流程**安全可控**。

- Worker 采用**按需加载策略**，运行时依据任务进展自主选择并加载 Tool、Skill，避免不必要的 **Token 消耗**，同时支持**动态切换执行策略**。

- 落地 **context 治理机制**：协调者根据当前阶段和用户意图动态选择相关字段注入上下文(goal、skill_index、profile 相关字段等)；**对话历史窗口裁剪，Worker 不读全量会话**，降低上下文污染与 token 浪费的同时保持上下文相关性。

- 设计了基于 Worker 的 **Profile 写入权限模型**，通过**路径白名单**控制各 Agent 的写入范围，Harness 运行时做**硬校验**防止越权修改。

- 建立**三层评测体系**（单元/链路/端到端），搭配**自动化 Trace 分析**，确保 Agent 行为**可复现、可回归**。
