## 版本 A · 标准版（推荐默认）

**个人职业操作系统（Personal Career OS）** | Python · FastAPI · LangGraph · React · SSE  
*2025 – 至今 · 个人项目*

面向 IT 从业者的 AI 职业规划与简历交付平台：以 `profile.json` 长期职业档案为记忆底座，打通「身份建模 → 能力资产 → 市场判断 → 策略推演 → JD 适配 → 可打印 HTML 简历」全链路，本地优先、对话驱动。

- 落地 **一主多从** 多智能体架构（协调者 + 身份/能力/市场/机会/策略/简历/资产 7 类 Worker）：协调者统一意图识别、派工与 SSE 流式合成；Worker 禁止互调，上游结论经 Harness 落档与会话上下文注入下游，实现认知分层解耦，避免「万能用户画像」单 Agent 膨胀。
- 构建 **Harness 运行时**：对话驱动的动态任务系统（milestone/work 强约束、纯对话启停/放弃）、Worker Run 内自选 Skill 按需加载、JD 推荐闸门与优化确认闸门；Tool 契约统一驱动档案读写、HTML 落盘与 `outputs_index` 索引登记。
- 打通 **端到端职业闭环**：职业初探五主题 + `experience_bank` 经历素材库 → 市场情报（联网浏览器 Tool）与 JD 匹配评估 → 多路径策略推演与三时间维度投递叙事 → 保守/标准/进取三档同轮多份 HTML、历史简历复用与 index 资产管理。
- 采用 **Python 单体 + React** 本机部署：FastAPI REST + SSE 逐字流式、LangGraph Agent 编排、跨会话 JSON 长期记忆；简历 HTML 纯正文可直打 PDF，真实档案与产出本地隔离不入 Git。

### 简历正文（可直接粘贴）

**个人职业操作系统（Personal Career OS）** | Python · FastAPI · LangGraph · React · SSE  
*2025 – 至今 · 个人项目*

垂直场景 Multi-Agent 产品：自研 Agent Harness，将 IT 从业者「职业认知 → 市场判断 → JD 策略 → 可打印简历」长流程拆为 **协调者 + 7 域 Worker**，以 `profile.json` 为跨会话长期记忆，对话驱动、本地优先交付。

- 设计并实现 **一主多从调度**：协调者只做意图识别、任务拆分、派工与 SSE 流式合成（不执行业务深挖）；7 类 Worker 职责互斥、**禁止互调**；上游 `structured_output` 经 Harness 落档 / 写入 `session_state` 后注入下游，避免「万能用户画像 Agent」的上下文膨胀与职责漂移。
- 自研 **Agent Harness 运行时**（非 LangChain 薄封装）：Prompt / Skill / Tool / Task / Storage 五类平台服务同进程暴露；Tool 注册表统一驱动档案读写、动态任务图、HTML 落盘与 `outputs_index`；**5+ 对话闸门**（深度探讨、JD 不推荐仍继续、优化确认等）实现 HITL，Task 层 `milestone/work` 强约束流程，Worker **禁止直出 SSE token**。
- 落地 **Context Engineering**：协调者派工仅传 `goal + context + skill_index`（不预加载 Skill 正文）；Worker Run 内 **自选 `load_skill`**（初探 / JD 对齐 / 简历模块化三 Skill），Harness 校验 `allowed_workers` 后按需注入；长期事实按域切片读 `profile.json`，Skill 与 Prompt 分离，新增业务能力 **零改协调者 Prompt**。
- 打通 **端到端职业 Agent 闭环**：五主题初探 + `experience_bank` → Browser Tool 公开市场情报与 JD 评估 → 策略三时间维度推演 → **同轮输出保守 / 标准 / 进取三档 HTML 简历**；历史产出 index 管理与复用，HTML 纯正文可直打 PDF。
- 按 **Eval 驱动迭代**：**94** 条 pytest case（L1 **88** + LLM **6**；分类覆盖 ≥23，见 `backend/tests/eval/CASES.md`）；2026-05-31 L1 全绿；Worker **ReAct + LiteLLM** 已落地（`feat/real-agent-worker-react`），无 Key 时 L1 走 `react_mocks`。

**一句话（空间极限时替换项目描述）**：基于 LangGraph 自研 Harness 的垂直 Multi-Agent 系统，协调者调度 7 域 Worker，对话闸门 + 档案切片 + Skill 按需加载，完成职业规划到三档 HTML 简历的本地闭环。

### 面试官深挖点（每个 bullet 对应 1–2 个必考题）

| 一主多从 | 为什么不用 AutoGen Group Chat / 单 Agent？ | 认知域不同（身份/能力/市场/策略/交付）；协调者 = 组织里的「管理层」做信息精炼，不是微服务乱拆；Worker 互调会导致 context 复制与职责边界模糊 |
| 协调者不干活 | 协调者和 Worker 边界怎么划？会不会协调者越来越胖？ | 协调者禁止 JD 打分、改简历、写 profile；只做派工 + 合成 + 闸门引导；业务规则进 Skill，工具约束进 Prompt，Harness 管状态 |
| Harness 自研 | 和直接 LangGraph + LangChain Tools 有什么区别？ | Harness = 职业 OS 运行时：Task 强约束、闸门、存储契约、Skill 注册表、审计 trace；不是「调 API 的胶水」 |
| Worker 不直出 SSE | 为什么 Worker 结果不能流式给用户？ | 统一对话入口与产品人格；Worker 出 `structured_output`，协调者控制话术与闸门；避免多 Agent 抢麦 |

| 5+ 对话闸门 | HITL 怎么设计？会不会打断体验？ | pre-turn 闸门（进深度探讨前）/ mid-flow（JD 不推荐仍继续）/ pre-delivery（优化确认）；核心版本无独立按钮，自然语言确认 |
| Browser Tool | 联网失败怎么办？ | 公开情报检索 + 来源标注 + 失败降级（仅用 profile 已有 market 数据继续）；不伪造检索结果 |

| 三档 HTML 同轮 | 三档差异是什么？怎么保证不 hallucinate 经历？ | 保守/标准/进取 = 表述力度与 JD 对齐度，不是编造经历；素材来自 `experience_bank` + 用户确认事实；eval 查「无证据断言」 |

## 版本 D · 系统设计 / 全栈侧重

**AI 职业规划与简历交付平台** | FastAPI · LangGraph · React 19 · TypeScript · SSE  
*2025 – 至今 · 个人全栈项目*

本地优先的职业 Agent 产品：前端对话 + 表单 + 任务进度 + 简历 index 管理；后端 Python 单进程承载 API、Harness 与全部 Agent Run。

- **可打印交付物**：简历 HTML 纯正文结构，浏览器直打 PDF；支持历史简历打开/删除与 index 资产管理。

### 面试深水区速答

| 问题 | 回答要点 |
|:---|:---|
| 为什么 Multi-Agent，而不是一个 Agent？ | 认知域不同（身份/能力/市场/策略/交付），单 Agent Prompt 会膨胀且难维护；协调者做信息精炼与派工，对齐「组织分工」而非微服务过度拆分。 |
| Worker 之间如何传上下文？ | **禁止互调**；协调者将上游 `structured_output` 写入 `session_state` 或经 Harness 落档，派下游时注入 `context`。 |
| Harness 管什么、模型管什么？ | Harness 管 Tool 注册、权限/闸门、Task 状态、存储契约、Skill 加载、trace；模型管域内推理与工具选择（含 Worker 内自选 Skill）。 |
| 上下文太长怎么办？ | 长期事实进 `profile.json` 切片注入；Skill 按需加载；Worker 只收 goal+context，不全量灌会话历史；协调者合成时压缩上游结论。 |
| 怎么证明不是 Demo？ | 对话闸门 + Task 强约束 + 结构化落档 + HTML/index 可交付；**94 pytest** 覆盖闸门/派工链/三档/降级/ReAct（`tests/eval/CASES.md`）；trace JSONL 可 grep。 |
