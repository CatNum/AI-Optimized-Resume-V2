# 简历项目描述 — AI-Optimized-Resume-V2

## 重点

- **定位**：面向 IT 从业者的 **Personal Career OS**——长期 `profile.json` 记忆 + 对话驱动「初探 → 市场/JD → 策略 → 可打印 HTML 简历」，本地优先（FastAPI + React + SSE）。
- **架构卖点**：**协调者 + 7 域 Worker** 一主多从；自研 **Harness**（Tool / Skill / Task / Storage / Trace）；Worker **禁止互调、禁止直出 SSE**；协调者 **LiteLLM 真流式** synthesize。
- **工程卖点**：**8 类对话闸门**（HITL）+ 初探建档表单 + JD 前置校验；**3 个 Skill** 包 Worker 内 `load_skill` 按需加载；**157** 条 pytest（**6** 条 `@llm`，见 `backend/tests/eval/CASES.md`）。
- **投递建议**：Agent / LLM 应用岗用 **版本 C**；全栈用 **版本 D**；一行摘要用 **版本 E**；面试前翻 **讲述提纲 + 深挖表**。
- **诚实边界**：Browser 降级、三档 HTML 顺序复用、部分 PRD 细流程仍在迭代——简历勿写未落地能力；文末有「勿夸大」清单。

> 下文各「简历正文」块可直接复制到简历「项目经历」。指标以仓库当前代码为准；更新前在 `backend/` 执行：`uv run pytest tests/ --collect-only -q`。

## 版本 A · 标准版（推荐默认）

**个人职业操作系统（Personal Career OS）** | Python · FastAPI · LangGraph · LiteLLM · React · SSE  
*2025 – 至今 · 个人项目*

面向 IT 从业者的 AI 职业规划与简历交付产品：以 `profile.json` 为跨会话长期记忆，打通「身份初探 → 能力资产 → 市场/JD 评估 → 策略推演 → 三档 HTML 简历」全链路；**本地优先**、对话驱动、档案与产出目录隔离不入 Git。

- 落地 **一主多从** Multi-Agent（协调者 + 身份/能力/市场/机会/策略/简历/资产 **7** 类 Worker）：协调者负责意图分析、派工与 **SSE 流式合成**；Worker **禁止互调**，上游 `structured_output` 经 Harness 落档 / `session_state` 注入下游，避免单 Agent 上下文膨胀。
- 自研 **Agent Harness 运行时**：统一 Tool 注册表（档案读写、`delegate_worker`、`write_resume_html`、`register_outputs_index` 等）；**8 类对话闸门**（深度探讨、JD 不推荐仍继续、优化确认、初探完成等）；`milestone/work` 任务强约束；Worker Run 内 **自选 `load_skill`** 加载三阶段 Skill 包。
- 打通 **端到端职业闭环**：初探五主题 + `experience_bank` 素材库 → 市场/JD 评估（含 JD 前置校验）→ 策略三时间维度叙事 → **保守/标准/进取** 三档同轮 HTML；`output/YYYY-MM-DD/` + `index.html` 资产管理与历史复用。
- 工程化交付：**157** 条 pytest（L1 主路径 + **6** 条 LLM eval）；协调者/Worker **ReAct + LiteLLM**（无 Key 时 L1 走 `react_mocks`）；**trace JSONL** 记录 delegate / skill / tool 便于失败归因；前端 Chat 消费 **`gate` SSE 事件** 与任务进度只读展示。

### 简历正文（可直接粘贴）

**个人职业操作系统（Personal Career OS）** | Python · FastAPI · LangGraph · LiteLLM · React · SSE  
*2025 – 至今 · 个人项目*

基于 **LangGraph** 的垂直 Multi-Agent 产品：自研 **Agent Harness**，将「职业认知 → 市场判断 → JD 策略 → 可打印简历」长流程拆为 **协调者 + 7 域 Worker**，以 `profile.json` 为跨会话记忆；对话驱动、本地优先、**协调者 LiteLLM 真流式** 统一用户出口。

- **一主多从调度**：协调者只做 analyze / 派工 / synthesize（不执行业务深挖）；7 Worker 职责互斥、**禁止互调**；下游仅收 `goal + context + skill_index`，上游结论经 Harness **落档** 后注入，控制 context 漂移。
- **Harness 运行时**（非框架薄封装）：Prompt / Skill / Tool / Task / Storage / Trace 同进程；**8 类自然语言闸门** + `milestone/work` 强约束；Worker **禁止直出 SSE token**；Tool 契约驱动 HTML 落盘与 `outputs_index` 登记。
- **Context Engineering**：三 Skill（`career-inner-exploration` / `career-jd-alignment` / `resume-module-optimize`）由 Worker **Run 内 `load_skill`**；`allowed_workers` 校验；长期事实按域切片读 `profile.json`；新增业务能力 **零改协调者 Prompt**。
- **端到端闭环**：初探建档 + `experience_bank` → JD 评估与策略推演 → 同轮 **保守/标准/进取** 三档 HTML；`browser_fetch` 公开情报 Tool（超时/失败降级）；前端 **`event: gate`** 确认流。
- **Eval 驱动**：**157** pytest、分类覆盖闸门/派工链/Tool/三档/降级（`tests/eval/CASES.md`）；**6** 条 `-m llm` 验真推理（需 `LLM_API_KEY`）；golden path 含 `optimize_confirm` 闸门链。

**一句话（极短替换）**：LangGraph + 自研 Harness 的垂直 Multi-Agent，协调者调度 7 Worker，闸门 + 档案切片 + Skill 按需加载，完成职业规划到三档 HTML 简历的本地闭环。

### 面试官深挖点

| 简历 bullet | 可能追问 | 核心答法 |
|:---|:---|:---|
| 一主多从 | 为何不用 Group Chat / 单 Agent？ | 认知域不同；协调者 = 管理层做信息精炼；Worker 互调会复制 context、模糊边界 |
| 协调者不干活 | 边界会不会膨胀？ | 禁止 JD 打分、改简历、写 profile；规则进 Skill，约束进 Prompt，状态进 Harness |
| Harness 自研 | 和 LangChain 套壳有何不同？ | 职业 OS 运行时：Task、闸门、存储契约、Skill 注册、审计 trace |
| Worker 不直出 SSE | 为何不能 Worker 流式？ | 统一人格与闸门话术；`structured_output` 由协调者 synthesize |
| Skill 按需加载 | 为何协调者不指定 skill？ | 同 Worker 多路径；预指定绑死流程；索引 + 自选更灵活 |
| 8 类闸门 | HITL 如何少打断？ | pre-turn / mid-flow / pre-delivery；自然语言确认，核心版无硬按钮 |
| browser_fetch | 联网失败？ | 公开 URL + 来源字段；失败降级用已有 `market.*`，不伪造检索 |
| 157 pytest | eval 怎么分层？ | L1 组件 + e2e 轨迹 + eval golden/llm；`-m llm` 验真推理质量 |
| 三档 HTML | 如何避免编造经历？ | 三档 = 表述力度与 JD 对齐度；素材来自 `experience_bank` + 用户确认事实 |

## 版本 D · 系统设计 / 全栈侧重

**AI 职业规划与简历交付平台** | FastAPI · LangGraph · React 19 · TypeScript · SSE  
*2025 – 至今 · 个人全栈项目*

本地优先职业 Agent 产品：React 对话 UI（SSE 流式 + **闸门确认** + 任务进度 + 上下文用量指示）+ Python 单进程承载 API、Harness 与全部 Agent Run。

- **前后端边界**：UI 仅 REST/SSE 对接 `career_os`，不直连 LLM、不读写 `profile.json`；Worker 结构化结果经协调者合成后流式展示。

- **可交付物**：简历 HTML 纯正文（`@media print` 友好）；`index.html` 列表打开/删除；初探 **Explore Intake** 表单与建档 API 对齐 PRD。

**JD golden path（API 手测）**：

```bash
# 1) 粘贴 JD → event: done + token
# 2) 「继续制定策略」→ event: gate（optimize_confirm）
```
