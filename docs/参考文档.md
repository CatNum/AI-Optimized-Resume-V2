# 职业规划 AI Agent 边界参考文档

## 重点

- **核心边界**：职业规划 Agent 不是“全能人生顾问”，而是帮助用户完成职业方向决策、能力成长路径和行动执行闭环中的可辅助认知部分。
- **三空间映射**：职业规划的关键不是单纯匹配岗位，而是持续对齐 `Personality Space`、`Capability Space` 和 `Market Space`。
- **Agent 分层**：成熟的职业规划 Agent 应拆分为 `Identity Agent`、`Capability Agent`、`Market Agent`、`Strategy Agent` 和 `Execution Agent`，避免把用户画像做成万能桶。
- **能力图谱壁垒**：`Capability Agent` 的价值不是维护技能标签，而是构建 `Dynamic Skill Graph`，推演能力迁移和职业资本演化。
- **最终价值**：职业规划 Agent 的真正边界不是 `Job Matching`，而是 `Capability Evolution`，帮助用户降低长期职业决策的试错成本。

## 一、先定义：它不是“全能人生顾问”

设计“人生规划类 AI Agent”，尤其是“职业规划 AI Agent”，核心不是“功能越多越好”，而是：

> **Agent 到底替用户承担哪一部分认知决策。**

边界划不好，会出现两个极端：

* 太窄 → 只是简历工具 / 岗位推荐器
* 太宽 → 变成“人生导师”，失去可执行性和可信度

一个成熟的职业规划 Agent，合理边界应该是：

> 帮用户完成「职业方向决策 + 能力成长路径 + 行动执行闭环」

而不是：

* 替用户决定人生意义
* 替用户做价值观选择
* 替用户承担风险
* 替用户做最终决定

### 1.1 Agent 的职责边界

它应该负责四类认知辅助。

### 1.2 信息理解（Understanding）

理解用户：

* 当前阶段
* 技能结构
* 兴趣倾向
* 性格偏好
* 资源约束
* 风险承受能力
* 长期目标

这是“用户理解层”，但不能被做成一个巨大的万能桶。

用户理解至少要拆成两类不同对象：

* `Identity Agent`：理解“你是谁”
* `Capability Agent`：理解“你会什么”

### 1.3 机会建模（Opportunity Modeling）

理解世界：

* 行业变化
* 岗位趋势
* AI 替代风险
* 薪资结构
* 技术演化
* 地域机会
* 创业 vs 打工

这是“世界模型层”。

### 1.4 路径推演（Path Simulation）

这是最核心的 Agent 能力。

它不是“推荐岗位”。

而是：

> 模拟不同职业路径未来 3 到 10 年的可能结果。

例如：

| 路径 | 3 年后 | 风险 | 上限 | AI 风险 |
| --- | --- | --- | --- | --- |
| 前端开发 | 中等收入 | 高竞争 | 中 | 高 |
| AI 应用工程 | 快速增长 | 技术变化快 | 高 | 中 |
| Web3 infra | 高波动 | 行业周期强 | 极高 | 中 |
| 内容 + AI 个人 IP | 不稳定 | 依赖个人品牌 | 高 | 低 |

这已经不是“搜索”。

而是：

**Career Simulation Engine（职业路径模拟引擎）**

这是职业 Agent 的真正壁垒之一。

### 1.5 动态行动系统（Execution Layer）

大多数产品死在这里。

用户不是缺建议。

用户缺：

* 持续反馈
* 低摩擦行动
* 外部监督
* 成长节奏
* 情绪稳定器

所以 Agent 必须有：

* 周目标
* 学习路径
* 项目实践
* 进度检查
* 简历更新
* 面试反馈
* 技能图谱变化

这是：

**Career Operating System（职业操作系统）**

## 二、职业规划的本质：三个空间的映射

很多 AI Agent 产品的问题在于：

> 把“用户画像”做成一个巨大的万能桶。

结果是：

* 没有结构化能力
* 无法推演成长
* 无法做职业迁移
* 无法形成长期职业操作系统

职业规划真正要处理的是三个空间的映射：

```text
Personality Space（人格 / 动机 / 偏好）
Capability Space（技能 / 经验 / 可迁移能力）
Market Space（岗位 / 行业 / 趋势 / 机会）
```

因为：

**人喜欢的事情 ≠ 人擅长的事情**

更重要的是：

**市场需要的事情 ≠ 你当前会的事情**

所以必须拆。

### 2.1 用户画像 Agent ≠ 技能图谱 Agent

它们属于两种完全不同的建模对象。

| Agent | 建模对象 | 回答的问题 | 变化速度 |
| --- | --- | --- | --- |
| `Identity Agent` | “你是谁” | 你偏好什么？ | 通常较慢 |
| `Capability Agent` | “你会什么” | 你能做什么？ | 动态变化 |
| `Market Agent` | “世界需要什么” | 哪些机会值得关注？ | 快速变化 |

这三个维度在职业规划里非常关键。

职业规划 Agent 的核心价值，不是“猜你喜欢什么”，而是发现：

```text
你想做什么
你能做什么
市场需要什么
```

三者之间的差距。

## 三、建议的 Agent 分层架构

推荐拆成 5 层。

### 3.1 Layer 1：Identity Agent（身份认知层）

`Identity Agent` 负责建模相对稳定的东西。

它回答的是：

> “你适合什么样的长期工作状态？”

而不是：

> “你能干什么？”

它负责：

* 兴趣
* 动机
* 性格
* 价值观
* 能量来源
* 风险偏好
* 工作偏好
* 长期价值观

它更像：

**心理学 + 行为学模型**

输出可能是：

```text
适合高变化环境
不适合高重复工作
对创造性工作有长期耐力
```

注意：

**这些特征通常变化很慢**

所以 `Identity Agent` 不应该频繁重写用户画像，也不应该承担技能推演、岗位匹配和行动监督。

### 3.2 Layer 2：Capability Agent（能力分析层）

`Capability Agent` 负责建模动态能力系统。

它回答的是：

> “你现在能做什么，以及你可以迁移到哪里？”

它负责：

* 技能树
* 知识结构
* 项目经验
* 实践证据
* 迁移能力
* AI 杠杆能力
* 学习速度
* 能力成长轨迹

但真正高级的能力图谱，不是 skill list。

而是：

**Dynamic Skill Graph（动态技能图谱）**

例如：

```text
Backend Engineering
 ├── API Design
 ├── Distributed Systems
 ├── System Reliability
 └── High Concurrency
```

以及：

```text
AI Agent Engineering
 ├── Prompt Engineering
 ├── Workflow Orchestration
 ├── RAG
 ├── Tool Calling
 └── Multi-agent Systems
```

这意味着 Agent 可以推演：

**“你距离某个职业还差什么能力”**

这里要特别强调：

**AI 时代的职业规划，核心不是职业匹配**

而是：

> 人类能力 × AI 杠杆后的复利增长。

### 3.3 Capability Agent 的关键壁垒：能力迁移

职业规划本质上是“能力迁移问题”。

例如，用户现在是：

```text
Java Backend Engineer
```

Agent 要推演能不能转：

* AI Engineer
* AI Infra
* Web3 Infra
* AI Product
* AI Automation Consultant

这时候，只有技能图谱才能做：

**Capability Transfer（能力迁移）**

例如：

```text
Backend Engineering
  -> API Design
  -> Distributed Systems
  -> System Reliability
```

这些能力其实能迁移到：

```text
AI Infra
MCP Server
Agent Runtime
Workflow Engine
```

这才是高级职业规划。

### 3.4 Capability Agent 的推理对象不是标签

它真正要做的不是记录：

```text
用户会 Python
```

而是理解能力之间的关系。

例如：

```text
会 Kubernetes
≠
会 AI Infra
```

但：

```text
Kubernetes
+ Distributed Systems
+ Observability
```

可能意味着：

```text
适合转 AI Platform Engineering
```

用户每完成：

* 一个 AI Agent 项目
* 一个自动化工作流
* 一次公开分享

系统都可能更新：

```text
AI Workflow +5
System Design +2
Communication +8
```

于是 Agent 可以持续推演：

**“用户正在形成什么职业资本”**

这就是 `Capability Portfolio`（能力资产组合）。

岗位会快速变化，但底层能力迁移会越来越重要。

未来可能不存在传统意义上的：

```text
前端工程师
```

而更接近：

```text
AI Interface Builder
Human-AI Interaction Designer
Workflow Composer
```

所以职业规划 Agent 的核心不是 `Job Matching`。

而是：

**Capability Evolution（能力进化）**

### 3.5 Layer 3：Market Agent（市场认知层）

这是很多产品缺失的。

它负责：

* 行业趋势
* 人才供需
* AI 替代概率
* 工资变化
* 创业机会
* 技术周期

例如，Agent 应该知道：

* 纯 CRUD 开发价值下降
* AI Workflow Engineer 上升
* AI Native PM 出现
* 单纯 PPT 咨询顾问被压缩
* “懂业务 + AI 自动化”的人会稀缺

这一层本质是：

**宏观职业推演系统**

### 3.6 Layer 4：Strategy Agent（职业战略层）

这是“大脑”。

它不直接等于长期记忆，也不等于单个画像 Agent。

它应该同时读取：

```text
Identity + Capability + Market
```

然后做职业推演。

它做：

**多路径推演**

例如：

| 路线 | 方向 |
| --- | --- |
| 路线 A | 继续后端 → 转 AI infra |
| 路线 B | 转 AI 产品 |
| 路线 C | 做 AI + 内容个人品牌 |
| 路线 D | 进入 Web3 AI Agent infra |

然后输出：

* 风险
* 时间成本
* 收益上限
* 路径依赖
* 不可逆决策
* 失败恢复能力

这里开始真正像：

**人生策略系统**

而不是求职工具。

### 3.7 Layer 5：Execution Agent（执行层）

它负责：

* 拆解目标
* 每日行动
* 学习计划
* 面试准备
* 简历优化
* 项目管理
* 监督反馈

这是：

**“教练型 Agent”**

不是咨询型 Agent。

## 四、哪些东西绝对不能让 Agent 决定

这是边界设计里最重要的一部分。

### 4.1 不应该替用户定义人生意义

AI 不该说：

* 你应该创业
* 你应该结婚
* 你适合躺平

这是危险边界。

### 4.2 不应该替用户做不可逆重大决策

例如：

* 裸辞
* All in 创业
* 大额投资
* 移民

AI 可以：

* 给概率
* 给风险
* 给模拟

但不能替用户做决定。

### 4.3 不应该让用户形成情感依赖

很多“人生导师 Agent”最后会变成：

* 情感寄托
* 精神依赖
* 认知控制

这是危险方向。

职业 Agent 应该更像：

**战略参谋 + 教练**

而不是：

**精神导师**

## 五、真正高级的职业 Agent，不是“推荐”

真正高级的职业 Agent，不是“推荐”。

而是：

**降低人生试错成本**

它的核心价值不是告诉你答案。

而是帮你：

* 更快验证方向
* 更低成本试错
* 更早发现趋势
* 更少浪费几年时间
* 更持续积累复利能力

本质上，它是：

**人生搜索引擎 + 模拟器 + 操作系统**

## 六、如果是 AI Native 架构，建议采用多 Agent

不要做单 Agent。

建议：

| Agent | 职责 | 边界 |
| --- | --- | --- |
| `Identity Agent` | 用户画像 | 建模人格、动机、偏好等相对稳定因素 |
| `Capability / Skill Agent` | 技能图谱 | 建模技能、项目、实践经验、学习速度和能力迁移 |
| `Market Agent` | 行业趋势 | 建模岗位、行业、技术周期和市场机会 |
| `Strategy Agent` | 路径推演 | 读取 `Identity + Capability + Market`，做多路径模拟和策略建议 |
| `Execution Agent` | 行动监督 | 把策略拆成目标、计划、实践、反馈和复盘 |
| `Reflection Agent` | 周期复盘 | 复盘行动结果，校准画像、能力图谱和策略 |
| `Opportunity Scout Agent` | 机会发现 | 持续发现岗位、项目、合作和市场窗口 |

`Memory Agent` 不建议作为一个万能业务 Agent。

它更适合作为数据底座：

* 记录长期用户成长数据
* 保存历史决策与反馈
* 支撑其他 Agent 读取上下文

但它不应该替代 `Identity Agent`、`Capability Agent` 或 `Strategy Agent` 的业务判断。

所以更合理的是：

**Strategy Agent 做 orchestrator（总调度）**

但它的判断必须建立在明确分工的 Agent 输出之上。

## 七、一个真正有壁垒的职业 Agent，核心资产是什么

不是模型。

不是 Prompt。

而是三类长期资产。

### 7.1 长期用户成长数据

例如：

* 学习行为
* 转型成功率
* 职业路径
* 决策后果

### 7.2 职业路径图谱

这是最值钱的数据。

例如：

```text
Java Backend
  -> AI Infra
  -> AI Agent Engineering
  -> AI Platform Architect
```

以及：

```text
哪些路径成功率高
哪些转型最容易失败
```

### 7.3 世界模型更新能力

因为职业世界变化太快。

尤其 AI 时代。

所以：

> 静态职业数据库会迅速失效。

Agent 必须持续学习：

* 新岗位
* 新工具
* 新组织结构
* AI 自动化趋势
* 市场需求变化

## 八、最后一句话总结

职业规划 AI Agent 的真正边界，不是：

> “帮用户找到工作”

也不是：

> “替用户决定人生”

而是：

> “帮助用户持续进化自己的职业资本，并降低长期职业决策的试错成本。”

换句话说：

**职业规划 Agent 的核心不是 Job Matching，而是 Capability Evolution。**
