### 5.4 职业战略与投递策略、三时间维度与优化确认

> 本阶段在 **市场/岗位分析（[B03 流程 · 市场岗位分析](./B03.%20流程-市场岗位分析%20PRD.md)）** 之后、**简历优化（[B06 流程 · 简历优化](./B06.%20流程-简历优化%20PRD.md)）** 之前；探讨须 **引用** `exploration.summary`、`capability.*`、`market.*` 与 `career.*`，避免与已确认的内心意向和能力事实背离。

#### 5.4.1 多轮探讨

策略智能体读取身份、能力、市场三层结果，先做多路径职业战略推演；当用户选择具体 JD / 机会继续时，再围绕该机会对齐投递策略：身份初探结论在该机会下的含义、能力侧当前能力与迁移能力如何被叙事化、该机会对下一跳和 3–5 年路径的影响。

策略智能体不重新做完整初探，不推翻市场智能体或岗位/机会智能体的事实判断。**进行中的 JD/机会流程** 中，岗位/机会 Worker 的评估结论须由 **入口编排（协调者）** 在派工 `strategy` 时 **注入**（**当前 session** 工作上下文，存于 `state.json` 的 `prior_results`；**换会话清空**，跨会话读 `profile.json`），策略 Worker **不得** 直接向岗位/机会 Worker 索取或接收直连上下文，也不应仅依赖用户复述。

若探讨中发现新的身份偏好、能力事实或市场事实，由 **协调者** 另行派工对应 Worker 更新并落档，而不是由策略智能体自行写入未经确认的新事实；Worker 之间 **不得** 互相调用。

无具体 JD 时，本阶段可只更新 `strategy.path_options`、`strategy.selected_strategy` 与 `career.*`，不进入 [B06 流程 · 简历优化](./B06.%20流程-简历优化%20PRD.md) 简历优化。

#### 5.4.2 三时间维度（长期策略与当前机会均须呈现）

| 维度 | 内容 | 存储 |
|------|------|------|
| 当前能力 | 当前能力资产、强项、短板、证据缺口；若有 JD，则补充与 **该 JD** 的匹配情况 | 更新 `career.current_assessment`、`capability.evidence_gaps` |
| 下一跳 | 6–18 个月路径影响、简历侧重、能力迁移重点；与身份偏好/约束是否一致 | 更新 `career.next_hop`、`strategy.selected_strategy` |
| 3–5 年影响 | 路径 A/B/C 及长期履历标签影响（与初探 `horizon_3_5y` 对照） | 更新 `career.horizon_3_5y`、`strategy.path_options` |

用户 **显式选择** 采纳的路径/策略后写入 JSON，供 简历智能体默认对齐。

#### 5.4.3 「优化确认」的定义

**优化确认** = 策略智能体在 `structured_output` 中产出确认问句（如 `gate_prompt`），由 **协调者转述** 后在对话中呈现；用户以自然语言或 [00 附录 B](./00.%20职业规划%20Agent%20PRD.md#附录-b确认话术建议) 建议话术 **明确表示同意** 后方成立。**核心版本不使用** 独立 UI 确认按钮。

- 问句示例（策略产出、协调者转述）：「是否确认按 **该岗位描述** 优化简历？」
- 认可答复示例：`确认按该 JD 优化简历`、`确认优化`（语义等价即可，不必逐字匹配）
- 未确认：可持续探讨、更新 JSON；**不** 生成最终简历 HTML。
- 已确认：进入 [B05 流程 · 简历复用](./B05.%20流程-简历复用%20PRD.md) 复用判断 → [B06 流程 · 简历优化](./B06.%20流程-简历优化%20PRD.md) 多选档位 → 简历智能体 **按档各生成一份** HTML（`write_resume_html` + `html_deliveries`）→ 资产智能体 `register_outputs_index` 登记索引。

> 与 [B02 流程 · 职业初探](./B02.%20流程-职业初探%20PRD.md)「初探完成确认」区分：前者结束 **价值探索**；后者启动 **简历生产**。
