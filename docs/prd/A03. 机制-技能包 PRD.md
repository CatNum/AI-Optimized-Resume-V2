#### 5.2.5 技能包机制（运行框架显式加载）

Skills 为 `.agent/skills/{name}/SKILL.md` 操作手册，由 **自建运行框架** 的 `load_skill(name)` 显式加载并注入子智能体上下文。

**外部参考**：[Superpowers](https://github.com/obra/superpowers)（智能体技能方法论库）。本项目技能包设计范式参考其 [brainstorming](https://github.com/obra/superpowers/tree/main/skills/brainstorming)：一次一问、分段确认、HARD-GATE、清单化步骤。

| 技能包 | 执行者 | 触发 | 产出 |
|-------|--------|------|------|
| `career-inner-exploration` | 身份智能体 + 能力智能体 | 当前 list 的 `list_type` 为 `explore` 或 `plan`；首次初探或复盘 | `exploration.*`、`resume.experience_bank`、`capability.*`、`career.*` 草案 |
| `career-jd-alignment` | 策略智能体 | `list_type=jd` 且 JD 评估已完成（含用户确认仍继续） | 更新 `career.*`、`strategy.*`；直至用户确认优化简历 |
| `resume-module-optimize` | 简历智能体 | 入口编排 **指派**（用户已确认按 JD 优化 + 多选档位） | 自行拆分 `work`、改写正文；按档各一份 HTML（资产智能体协作落盘） |

资产智能体不加载上述技能包，职责按主路径时序划分：

- **优化前**（[B05 流程 · 简历复用](./B05.%20流程-简历复用%20PRD.md)，在 `resume-module-optimize` 之前）：扫描 `outputs_index` 与会话目录、给出 **复用建议**，用户确认复用 / 跳过 / 增量 / 新建；**不** 改写简历正文。
- **优化后**（[B06](./B06.%20流程-简历优化%20PRD.md) / [B07](./B07.%20流程-HTML%20交付%20PRD.md)，消费简历智能体正文产物）：文件名标签、HTML 落盘、更新 `outputs_index` 与 `index.html`、打开 / 删除（不提供应用内下载 .html，见 [B07 §5.7.5](./B07.%20流程-HTML%20交付%20PRD.md#575-打印-pdf-与本地留存)）。

**模式（初探技能包）**

| 模式 | 条件 | 清单 |
|------|------|------|
| 首次 | 无 `exploration.completed_at` | 完整清单：五主题 + 简历深挖 + 交叉/路径/summary（`phases.md`） |
| 复盘 | 已有 `completed_at` 且用户要更新 | 短路径：不重问五主题；**按需** 补简历素材 |

**与任务（[A02 机制 · 任务系统](./A02.%20机制-任务系统%20PRD.md)）**：里程碑由入口编排创建并与技能包绑定；`resume-module-optimize` 下 **`work` 由简历智能体创建** 并逐条 claim/complete。

任务与技能包绑定：因为技能都是针对某种技能单独定制的，所以这里可以绑定，但是正常来说应该是模型自主判断。

详见 [.agent/README.md](../.agent/README.md)。
