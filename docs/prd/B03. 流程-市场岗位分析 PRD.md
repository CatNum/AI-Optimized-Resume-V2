### 5.3 市场/岗位分析（含 JD 机会评估）

**前置条件**：`exploration.completed_at` 已存在（[B02 流程 · 职业初探](./B02.%20流程-职业初探%20PRD.md)）。

#### 5.3.1 定位

**市场智能体** 与 **岗位/机会智能体** 共同回答「世界需要什么」与「当前机会是否值得投入一次简历定制成本」。本阶段既支持无具体 JD 的岗位族/市场趋势讨论，也支持有具体 JD 时的机会评估；但不生成独立 JD 报告 HTML。

#### 5.3.2 输入

- 用户咨询岗位族、行业趋势、技术方向、AI 替代风险等市场问题。
- 用户 **粘贴** JD 全文，或口头描述一个具体机会。

#### 5.3.3 处理

0. **公开情报（联网浏览器 Tool，核心版本）**：**市场智能体** / **岗位/机会智能体** 在分析前或分析中，根据公司名、岗位族、行业或技术关键词调用 **联网浏览器 Tool**，拉取 **公开网页信息**（招聘站公开 JD、公司官网/新闻、行业报告摘要、技术社区公开讨论等），用于判断「世界需要什么」、行业趋势与机会窗口；对话中 **标注信息来源**（URL 或站点名）。拉取结果提炼后写入 `market.trend_notes[]`；若用于某次 JD 评估，同步记入该条 `market.opportunity_snapshots[].external_sources[]`。**须** 写入 `source_url`、`fetched_at`（[A01 §5.1.6](./A01.%20机制-职业档案%20PRD.md#516-profilejson-结构纲要)），供溯源审计。**仅** 使用公开可访问信息；**不** 替代用户粘贴的 JD 全文作为匹配主依据。
1. 市场分析：结合上一步公开情报 + 用户输入 + 档案已有 `market.*`，归纳岗位族、行业趋势、技术周期、供需变化、AI 替代风险、机会窗口，更新 `market.*`。
2. JD / 机会解析：职级、职责、必备项 / 加分项、技术栈、组织语境、隐含能力要求（有 JD 时以用户粘贴全文为主，公开情报作补充）。
3. 匹配：对照 `profile.json`（含 **`exploration`、`capability`、`market`、`career`**）、基线简历 Markdown（`resume.source_path`）、**`resume.experience_bank`** 及可选已有 HTML。
4. 结论：无具体 JD 时输出岗位族/市场判断；有具体 JD 时输出 **推荐 / 不推荐** + 理由（匹配度、硬伤、风险、与身份初探意向的一致性、与能力侧当前能力/迁移能力的一致性、与市场趋势的一致性）。

#### 5.3.4 输出

- **仅通过对话** 告知用户（不生成 JD 适配报告 HTML）。

#### 5.3.5 JD 建议闸门（软阻断，用户可覆盖）

| 结论 | 系统行为 | 默认后续 | 用户覆盖 |
|------|----------|----------|----------|
| **推荐** | 对话说明匹配点、与初探意向的一致性、可选风险 | 进入 [B04 流程 · 职业战略与投递策略](./B04.%20流程-职业战略与投递策略%20PRD.md) 职业战略与投递策略探讨 | — |
| **不推荐**或匹配不足 | **明确建议不要继续**，说明硬伤、匹配度、投递风险、与初探/长期意向的冲突；不隐瞒结论 | **暂停**；不默认生成简历 HTML | 用户 **确认仍继续** 后，同等进入 [B04 流程 · 职业战略与投递策略](./B04.%20流程-职业战略与投递策略%20PRD.md)（须再次提示风险） |

**两级确认（均在对话中询问，用户以自然语言或 [00 附录 B](./00.%20职业规划%20Agent%20PRD.md#附录-b确认话术建议) 明确回复；不使用 UI 按钮）**：

1. **继续确认**（仅在不推荐时出现）：智能体在对话中询问是否仍继续；用户确认后 → 记录至 `career.jd_override[]`（含 JD 指纹、时间、不推荐理由快照）。
2. **优化确认**（[B04 §5.4.3](./B04.%20流程-职业战略与投递策略%20PRD.md#543-优化确认的定义)）：策略智能体在对话中询问是否按该 JD / 机会优化简历；用户确认后 → 进入 [B05 流程 · 简历复用](./B05.%20流程-简历复用%20PRD.md) 复用 → [B06 流程 · 简历优化](./B06.%20流程-简历优化%20PRD.md) 多选档位 → **按档生成多份** HTML。

> 不推荐时 **默认不继续**；继续与优化两步确认可合并为一句实现，但语义上须区分「明知不匹配仍投递」与「确认生成简历」。

#### 5.3.6 公开信息与市场情报（联网浏览器 Tool）

**范围**：核心版本 **纳入**（非后续版本）；由运行框架向 **市场智能体** / **岗位/机会智能体** 暴露 **联网浏览器 Tool**（L7 基础设施，见 [00 PRD §4.6 / §6.1](./00.%20职业规划%20Agent%20PRD.md)）。

| 项 | 说明 |
|----|------|
| **用途** | 支撑「世界需要什么」：行业/岗位族趋势、技术周期、公司公开画像、机会窗口、AI 替代风险等 **外部事实**，避免仅依赖模型训练数据或用户口述 |
| **触发** | 用户咨询市场/岗位方向；粘贴 JD 且含公司名；编排调度市场/岗位步骤时 **默认尝试** 拉取与当轮主题相关的公开信息（实现可配置为必调/按需调） |
| **输入** | 公司名、岗位族、行业关键词、技术栈关键词等（从对话、JD、`profile` 推导） |
| **约束** | 仅访问 **公开** 信息；遵守 robots/速率限制（实现阶段）；日志与落盘 **不落** 用户简历/JD 全文；对话说明数据来自公开检索 |
| **落档** | `trend_notes[]` 每条含 `topic`、`summary`、`source_url`、`fetched_at`；JD 评估若引用联网情报，在对应 `opportunity_snapshots[].external_sources[]` 重复记录 URL 与时间 |
| **溯源审计** | 对话展示来源；档案字段与 [A01 `market.trend_notes[]` / `opportunity_snapshots[]`](./A01.%20机制-职业档案%20PRD.md#516-profilejson-结构纲要) 一致，便于事后核对 |
| **降级** | 联网失败、超时、无有效结果时：明确告知用户，改基于 **用户输入 + JD 文本 + 已有 `market.*` / `profile`** 继续分析，**不** 阻塞 JD 闸门与后续 B04–B07 主路径 |
| **边界** | 不替代 JD 软阻断/两级确认逻辑；不自动投递、不登录招聘站内网 |
