### 5.1 职业档案（长期记忆）

#### 5.1.2 对话增量更新

- 会话中识别到新事实（技能、项目、意向变化等）时，入口编排智能体**提议** 更新项。
- 用户同意后 merge 入 `profile.json`（含 `meta.updated_at` 版本信息）。

#### 5.1.3 简历输入

- 用户通过表单 **粘贴** 简历内容（核心版本不支持简历文件上传；见 [00 PRD §1.6](./00.%20职业规划%20Agent%20PRD.md) 范围表）。
- 系统将内容写入 `data/` 下独立 **Markdown** 文件，并在 UI 中 **可视化渲染** 供用户核对；`profile.json` 的 `resume.source_path` **仅存** 该文件相对 `data/` 的路径（如 `resume/source.md`），**不** 在 JSON 内嵌全文。
- 初探与优化智能体 **只读** 该 Markdown 基线，不改写文件正文（增量写入 `resume.experience_bank` 等字段）。

#### 5.1.4 长期记忆、职业资本与初探存储

以下内容 **仅存 JSON**，不单独生成 HTML：

**职业初探（[B02 流程 · 职业初探](./B02.%20流程-职业初探%20PRD.md)，用户确认进入并提交表单后、JD 前写入）**

- `exploration` — 见 [B02 §5.2.3](./B02.%20流程-职业初探%20PRD.md#523-初探结束与落档)；含内心需求、渴望、职业需要、当下重点、当前问题及初探摘要
- `resume.experience_bank` — 初探阶段 **简历深度追问** 补充的经历素材（[B02 §5.2.2](./B02.%20流程-职业初探%20PRD.md#522-对话依据与探索主题)），供后续 JD 匹配与简历优化引用；**不** 改写 `resume.source_path` 所指向的基线 Markdown
- `capability` — 能力资产组合；含技能图谱、能力迁移线索、证据缺口与 AI 杠杆能力，不等同于简历关键词列表
- `market` — 市场/岗位认知；含岗位族、行业趋势、技术周期、机会风险、AI 替代风险与具体 JD 快照
- `strategy` — 职业战略推演；含多路径比较、用户选择、路径风险、时间成本、收益上限与失败恢复能力

**长期规划（初探、市场分析与 JD 阶段逐步完善）**

- `career.current_assessment` — 当前能力评估（结构化 + 摘要）
- `career.next_hop` — 下一跳建议（含用户已选方案）
- `career.horizon_3_5y` — 3–5 年路径影响（含用户已选路径）
- 用户每次在「三时间维度」或「多路径推演」中的 **显式选择** 须回写 JSON（如 `career.selected_path_id`）；JD 阶段须 **引用** 初探结论、能力资产与市场判断，避免与已落档意愿冲突

#### 5.1.5 能力偏好标签（用于文件名与推荐）

**用途**：供 智能体推荐复用简历时参考；其中 **文件名** 中的 `{能力偏好摘要}` 由 **大语言模型动态选取**（见 [B07 [B07 流程 · HTML 交付](./B07.%20流程-HTML%20交付%20PRD.md).3](./B07.%20流程-HTML%20交付%20PRD.md#573-文件命名)），非简单拼接 `selected[]`。

**三类数据来源**（职责不同，不是三种「并列用户标签」）：

| 类型 | 说明 | 存储位置 |
|------|------|----------|
| **默认标签（词表）** | 系统预置 IT 常见方向，供表单多选 | `config/preference-tags-default.json`（[A01 附录 A](./A01.%20机制-职业档案%20PRD.md#附录-a默认能力偏好标签初版)），**不写入** `profile.json` |
| **用户已选** | 表单多选结果 | `preference_tags.selected[]` |
| **动态补充** | **默认词表外**的标签（历史交付命名沉淀；与词表外新词为同一集合） | `preference_tags.custom[]` |

**`custom[]` 沉淀（HTML 交付后，无二次确认）**

当 **资产智能体** 在 [B07 §5.7.3](./B07.%20流程-HTML%20交付%20PRD.md#573-文件命名) 生成 `{能力偏好摘要}` 时，若使用了 **不在默认词表** 中的新标签（如「边缘计算」），在用户 **已确认** 当次简历交付（含文件名）后，系统将当次 `outputs_index[].filename_tags[]` 中该类词表外标签 **按词义去重** 追加至 `preference_tags.custom[]`（同义、近义或表述变体视为同一标签，实现阶段归一化）。**词表外即 `custom[]` 范畴**。**不** 在对话中因口头偏好单独询问；`custom[]` 对用户隐藏。对话中仅提及、但未进入已确认文件名的标签 **不** 写入 `custom[]`。同轮多档共用同一摘要前缀时，**只沉淀一次**。

**文件名标签：大语言模型动态选取（生成 HTML 前）**

由 **资产智能体** 根据 **`profile.json` 全部相关内容**（含 `exploration`、`career`、基线简历 Markdown）及 **当前对话上下文**（本 JD、本轮优化目标、用户口头强调的方向）生成 **1–3** 个标签，拼入 `{YYYY-MM-DD}-{能力偏好摘要}.html`。

**候选池与优先级**（`custom[]` 仅存 **默认词表外** 的标签；词表内项来自 `selected[]` 或默认词表未选项）：

| 优先级 | 来源 | 说明 |
|--------|------|------|
| 1 | `preference_tags.selected[]` | 用户表单从默认词表多选，**优先选用** |
| 2 | 默认词表中 **用户未选** 的项 | 若与当轮 JD/上下文更贴切，**允许** 选用（如未勾「云原生」但本 JD 强依赖云原生） |
| 3 | `preference_tags.custom[]` | 默认词表外、历史交付已沉淀的标签 |

- 依据 **`profile.json` 与当轮 JD/对话** 按上表 1→2→3 选取；**不得** 为生成当次文件名而读取或照搬 `outputs_index`、历史 HTML **完整文件名** 或过往 `{能力偏好摘要}` 组合。
- 当 1–3 **均无合适标签** 时，模型 **生成** 新的词表外标签写入文件名（须符合下方字符约束）；**简历 HTML 生成且用户确认交付后**，将该新词按词义去重追加至 `custom[]`，供后续轮次作为优先级 3 选用。

**选取约束**：

- 最多 **3** 个标签，`-` 连接；单标签最长 **16** 字符；非法文件名字符替换为 `_`。
- **重名消歧**：完整主文件名 `{YYYY-MM-DD}-{能力偏好摘要}-{语义档位}` 与同会话目录或 `outputs_index` 已有记录冲突时，在 `{能力偏好摘要}` **末尾** 追加 `(1)`、`(2)` … 直至唯一（如 `…-后端-云原生(1)-标准.html`）。**允许** 标签组合与历史交付相同，不以强行换标签为目的一律消歧。
- 须在生成 HTML 时写入 `outputs_index[].filename_tags[]` 与 `optimization_level`（`保守`/`标准`/`进取`）留痕，便于复用判断与审计。
- 文件名 **必须** 以语义档位后缀 `-保守`/`-标准`/`-进取` 结尾，与用户当轮所选档位一一对应（**单档与多档均须**，见 [B07 §5.7.3](./B07.%20流程-HTML%20交付%20PRD.md#573-文件命名)）。
- 多档同轮生成时，能力偏好标签候选池可共用，但 **每档独立文件**，仅语义档位后缀不同。
- 选取理由可在对话中 **一句说明**（非必须写入文件名）。

#### 5.1.6 `profile.json` 结构纲要

> 下列 JSON 中 `//` 为 **中文含义备注**（文档说明用）；落盘文件须为合法 JSON，**不得** 含 `//` 注释。

```json
{
  "meta": {
    "version": 1,              // 档案 schema 版本号
    "updated_at": "ISO8601"    // 最近一次确认落档时间
  },
  "basic": {},                   // 基本信息（表单 [B01 §5.1.1](./B01.%20流程-对话入口与建档%20PRD.md#511-建档表单用户确认进入后)：姓名、联系方式、工作年限等）
  "skills": {},                  // 技能清单（表单采集 + 对话增量，结构化技能/熟练度）
  "intent": {},                  // 求职意向（目标岗位族、城市、薪资区间、到岗时间等）
  "constraints": {},             // 个人约束（地域、远程、加班、家庭、签证等硬性/软性限制）
  "exploration": {                // 身份初探（身份智能体 · [B02 流程 · 职业初探](./B02.%20流程-职业初探%20PRD.md)）
    "completed_at": null,        // 初探完成时间；null 表示未完成，JD 闸门不开放
    "inner_needs": "",           // 内心真实需求
    "desires": "",               // 渴望（理想工作状态、成就感来源）
    "career_needs": "",          // 职业需要（理性层面的岗位/行业/成长诉求）
    "priorities_now": "",        // 当下最重要（未来 6–12 个月优先事项）
    "current_problems": "",      // 当前问题（阻碍、焦虑、缺口）
    "summary": ""                // 初探摘要（用户确认后的总述）
  },
  "career": {                     // 长期职业路径与评估（策略智能体 · [B04 流程 · 职业战略与投递策略](./B04.%20流程-职业战略与投递策略%20PRD.md)）
    "current_assessment": {},    // 当前能力评估（强项、短板、与机会匹配摘要）
    "next_hop": {},              // 下一跳（约 6–18 个月路径、简历侧重、能力迁移重点）
    "horizon_3_5y": {},          // 3–5 年路径影响（长期履历标签、路径对照）
    "selected_path_id": "",      // 用户已选路径/策略 ID（多路径推演中的显式选择）
    "jd_override": []            // 用户在不推荐 JD 时仍继续的记录（见下表）
  },
  "capability": {                 // 能力资产组合（能力智能体 · [B02 流程 · 职业初探](./B02.%20流程-职业初探%20PRD.md)）
    "skill_graph": {},           // 技能图谱（技能节点、熟练度、证据关联）
    "transfer_paths": [],        // 能力迁移线索（从 A 能力/经历可迁移至 B 方向）
    "evidence_gaps": [],         // 证据缺口（策略/JD 阶段识别的待补强能力或经历）
    "portfolio_summary": ""      // 能力资产组合摘要（供匹配与简历智能体速读）
  },
  "market": {                     // 市场/岗位认知（市场 + 岗位/机会智能体 · [B03 流程 · 市场岗位分析](./B03.%20流程-市场岗位分析%20PRD.md)）
    "role_families": [],         // 关注的岗位族列表
    "trend_notes": [],           // 行业/技术趋势等观察（元素见下表；须含溯源字段）
    "opportunity_snapshots": []  // 具体 JD/机会评估快照（见下表）
  },
  "strategy": {                   // 职业战略推演（策略智能体 · [B04 流程 · 职业战略与投递策略](./B04.%20流程-职业战略与投递策略%20PRD.md)）
    "path_options": [],          // 多路径选项（路径 A/B/C 及利弊）
    "selected_strategy": {},     // 用户已选策略（含三时间维度对齐结论）
    "risk_notes": [],            // 路径/投递风险备注
    "last_reviewed_at": null     // 最近一次策略复盘时间
  },
  "resume": {                     // 简历原文与经历素材（表单 + 能力智能体）
    "source_path": "",           // 基线简历 Markdown 相对 data/ 的路径（如 resume/source.md）；正文不在 JSON
    "last_optimization_levels": [], // 上一轮多选档位：保守 | 标准 | 进取（供默认勾选）
    "experience_bank": {         // 经历素材库（初探深挖产出，§5.2.2.1 / B02）
      "items": [],               // 结构化经历条目（见下表）
      "narrative_summary": ""    // 经历素材摘要（200–500 字，供速读）
    }
  },
  "preference_tags": {            // 能力偏好标签（[A01 §5.1.5](./A01.%20机制-职业档案%20PRD.md#515-能力偏好标签用于文件名与推荐)）
    "selected": [],              // 表单多选（来自默认词表）
    "custom": []                 // 默认词表外标签（交付命名沉淀；对用户隐藏；按词义去重）
  },
  "outputs_index": []             // 已生成 HTML 简历索引（资产智能体维护）
}
```

**嵌套对象与数组元素含义**

| 路径 | 中文含义 | 典型内容 / 说明 |
|------|----------|-----------------|
| `career.jd_override[]` | 不推荐仍继续投递记录 | `jd_fingerprint`（JD 指纹）、`at`（时间）、`reason_snapshot`（不推荐理由快照） |
| `market.trend_notes[]` | 单条市场/趋势观察 | 见下表；**须** 含 `source_url`、`fetched_at` 以便溯源审计 |
| `market.opportunity_snapshots[]` | 单次机会评估快照 | JD 指纹、推荐/不推荐、匹配要点等；见下表 |
| `strategy.path_options[]` | 战略路径候选项 | `path_id`、路径名称、时间成本、收益上限、失败恢复、与初探一致性 |
| `strategy.selected_strategy` | 已选战略 | 当前采纳的路径 ID、三时间维度摘要、针对当前 JD 的投递叙事要点 |
| `capability.skill_graph` | 技能图谱 | 节点（技能名、层级）、边（关联/依赖）、证据指向 `experience_bank` 条目 |
| `capability.transfer_paths[]` | 能力迁移路径 | 源能力/经历 → 目标岗位能力、迁移条件与缺口 |
| `capability.evidence_gaps[]` | 证据缺口 | 能力或经历维度、缺口描述、建议补齐方式（当前版本仅记录，不触发执行层） |
| `resume.source_path` | 基线简历 Markdown 路径 | 相对 `data/`；正文存独立 `.md`，UI 可视化渲染；初探不改写该文件 |
| `resume.experience_bank.items[]` | 单条经历素材 | 见下表 |
| `outputs_index[]` | 单份 HTML 产物元数据 | 见下表 |

| `market.trend_notes[]` 字段 | 中文含义 |
|----------------------------|----------|
| `topic` | 观察主题（岗位族、技术方向、公司、行业等） |
| `summary` | 提炼后的观察结论（供对话与后续匹配引用） |
| `source_url` | **溯源**：公开网页 URL；仅用户口述未检索时填 `user_provided` |
| `fetched_at` | **审计**：信息获取或落档时间（ISO8601）；联网抓取时为抓取完成时间，用户口述时为写入档案时间 |

| `market.opportunity_snapshots[]` 字段 | 中文含义 |
|-------------------------------------|----------|
| `jd_fingerprint` | JD 指纹 |
| `recommendation` | `recommended` \| `not_recommended` |
| `match_highlights` | 匹配要点 |
| `blockers` | 硬伤 / 不匹配项 |
| `risks` | 投递或职业风险 |
| `evaluated_at` | 本次评估时间（ISO8601） |
| `external_sources[]` | 本快照引用的联网公开情报（0–n 条）；每项 **须** 含 `source_url`、`fetched_at`、`summary`（摘录） |

| `resume.experience_bank.items[]` 字段 | 中文含义 |
|---------------------------------------|----------|
| `period` | 时间段 |
| `org_or_project` | 公司或项目名称 |
| `role` | 担任角色 |
| `highlights[]` | 亮点/成果要点 |
| `skills_demonstrated[]` | 本条经历体现的技能 |
| `source` | 来源：`resume_gap`（简历未写清）或 `dialogue`（对话挖掘） |

| `outputs_index[]` 字段 | 中文含义 |
|------------------------|----------|
| `path` | 本机 HTML 文件路径 |
| `created_at` | 生成时间 |
| `optimization_level` | 优化档位：`保守` \| `标准` \| `进取`（与文件名语义后缀一致，[B06 流程 · 简历优化](./B06.%20流程-简历优化%20PRD.md)） |
| `filename_tags[]` | 当次 `{能力偏好摘要}` 中的能力偏好标签（按 §5.1.5 优先级选取或当轮新生词表外标签，[A01 §5.1.5](./A01.%20机制-职业档案%20PRD.md#515-能力偏好标签用于文件名与推荐)） |
| `jd_fingerprint` | 关联 JD 指纹（可选） |
| `session_date` | 所属会话目录日期 `YYYY-MM-DD`（可选，便于扫描） |

实现阶段 `basic` / `skills` / `intent` / `constraints` 及 `{}` 占位对象的具体键名，可在 `profile.example.json` 中与表单字段一一对齐；上表覆盖 PRD 主路径已引用的全部顶层与关键嵌套字段。
