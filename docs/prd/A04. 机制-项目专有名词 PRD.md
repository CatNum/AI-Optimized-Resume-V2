## 1. 目标

本文件用于登记项目内的专有名词，统一术语写法与中文解释，避免测试注释、代码注释和文档说明中对同一概念使用不同表达。

后续补充测试函数注释、代码注释或架构说明时，应优先参考本表。

---

## 2. 核心架构术语

| 术语 | 推荐写法 | 中文解释 |
|------|----------|----------|
| Agent | Agent（智能体） | 具备角色、提示词、工具和输出约束的任务执行单元。 |
| Coordinator | Coordinator（协调者） | 对内负责分析用户意图、选择 Worker、汇总结果；对外保持统一职业规划助手人格。 |
| Worker | Worker（工作者） | 被 Coordinator 派工的领域执行单元，例如 identity、market、resume。 |
| Harness | Harness（运行时执行器） | 统一承接工具执行、权限校验、任务操作、审计记录和平台服务调用的运行时边界。 |
| ToolRegistry | ToolRegistry（工具注册表） | 维护工具定义、可见范围和调用权限的注册表。 |
| Store | Store（存储层） | 对 profile、session、task、output 等本地文件数据的读写封装。 |
| Skill | Skill（技能包） | Worker 在运行中按需加载的领域操作手册。 |
| ReAct | ReAct（推理行动循环） | 模型先推理、再按需调用工具、再继续推理直到输出结构化结果的执行模式。 |
| LLM | LLM（大语言模型） | 用于分析、生成、总结、分类的模型调用能力。 |
| LiteLLM | LiteLLM（模型调用适配层） | 统一适配不同模型提供商的调用库。 |

## 3. 流程与状态术语

| 术语 | 推荐写法 | 中文解释 |
|------|----------|----------|
| pipeline | pipeline（主流程） | 当前产品唯一主路径，用 current_phase 控制阶段推进。 |
| phase | phase（阶段） | pipeline 中的当前位置，例如 explore、market、jd_analysis。 |
| explore | explore（探索阶段） | pipeline 的初始阶段，负责职业初探、身份和能力信息收集。 |
| market | market（市场阶段） | pipeline 中负责市场岗位分析的阶段。 |
| jd_analysis | jd_analysis（JD 分析阶段） | pipeline 中负责具体 JD 机会评估的阶段。 |
| resume_strategy | resume_strategy（简历策略阶段） | pipeline 中负责投递策略和简历优化策略的阶段。 |
| resume_optimize | resume_optimize（简历优化阶段） | pipeline 中负责生成简历交付物的阶段。 |
| current_phase | current_phase（当前阶段） | 存在任务列表元数据中的流程游标，是阶段过滤的主要依据。 |
| list_type | list_type（列表类型） | 会话或任务列表的业务类型标记；当前主路径主要使用 pipeline。 |
| gate | gate（确认门） | 需要用户确认后才能继续推进的关键决策点。 |
| pending gate | pending gate（待确认门） | 当前等待用户确认、拒绝或澄清的 gate。 |
| gate flags | gate flags（确认门标记） | gate 确认、拒绝或过期后写入会话状态的标记集合。 |
| flags | flags（确认标记） | gate 确认后写入会话状态的布尔标记集合。 |
| session_state | session_state（会话状态） | 当前会话在后端流转中的状态载体。 |
| prior_results | prior_results（历史 Worker 结果） | 本轮之前各 Worker 的结构化输出摘要。 |
| capability_bundle | capability_bundle（能力包上下文） | 派工时注入给 Worker 的可用技能、工具和上下文索引。 |

## 4. 业务领域术语

| 术语 | 推荐写法 | 中文解释 |
|------|----------|----------|
| JD | JD（岗位描述） | 用户提供的目标岗位信息，是市场分析、机会评估和简历优化的重要输入。 |
| profile | profile（职业档案） | 本地长期职业记忆，包含身份、能力、市场、策略、产物索引等结构化数据。 |
| exploration | exploration（职业初探） | 对用户职业动机、偏好、约束、能力素材的初始深挖结果。 |
| intake | intake（信息收集） | 用户进入 explore 前或 explore 中提交的基础信息收集结果。 |
| experience_bank | experience_bank（经历素材库） | 从简历和对话中沉淀出的可复用经历素材。 |
| outputs_index | outputs_index（产物索引） | 已生成简历页面等产物的登记索引。 |
| HTML | HTML（网页简历格式） | 当前简历交付的本地网页格式。 |
| PDF | PDF（打印导出格式） | 用户可通过浏览器打印或另存得到的导出格式。 |

## 6. 具体 Worker 名称

| 术语 | 推荐写法 | 中文解释 |
|------|----------|----------|
| identity | identity Worker（身份工作者） | 负责身份、动机、偏好和约束相关探索。 |
| capability | capability Worker（能力工作者） | 负责能力素材、经历库和能力图谱相关探索。 |
| market | market Worker（市场工作者） | 负责岗位族、市场趋势和公开情报摘要。 |
| opportunity | opportunity Worker（机会工作者） | 负责具体 JD 或机会是否值得继续投入的评估。 |
| strategy | strategy Worker（策略工作者） | 负责职业路径、投递策略和简历优化前策略判断。 |

## 7. 使用规则

### 7.1 测试函数注释

测试函数注释用于说明“这个测试验证什么行为”，不复述函数名。

推荐格式：

```python
def test_example():
    """验证 gate 确认后会推进 pipeline 当前阶段。"""
```

不推荐格式：

```python
def test_example():
    """验证 test_example 场景。"""
```

### 7.2 代码注释

代码注释用于解释关键流程的意图，不逐字解释代码，也不机械复述函数名。

推荐格式：

```python
# 无 LLM 环境下使用 mock，保证基础测试可确定性执行。
```

不推荐格式：

```python
# mock_run_worker_react 函数用于执行 mock_run_worker_react。
```

## 8. 后续维护规则

新增术语时，应满足至少一个条件：

1. 在代码、测试、提示词或 PRD 中多次出现。
2. 直接影响架构边界或测试注释表达。
3. 翻译成中文后容易产生歧义。
4. 是字段名、事件名、阶段名、Worker 标识或工具名。

新增后同步检查测试注释、代码注释和架构文档是否需要回收为统一写法。
